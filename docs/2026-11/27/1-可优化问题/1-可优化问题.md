## P0：正确性、费用和并发控制

### 1. 目标语言的文字体系判断会误伤同一文字体系

`src/modules/reader/selectionEligibility.ts` 根据目标语言对应的 Unicode Script 判断所选文本是否已经是目标语言。

例如目标语言为英语时，任何纯拉丁字母的单词都会被拒绝，因此会影响：

- 法语 → 英语。
- 德语 → 英语。
- 西班牙语 → 英语。
- 任何源语言和目标语言共用文字体系的组合。

建议：

- 必须拦截的只有纯标点、纯符号和空选区。
- 已经存在的嵌入译文 DOM 标记可继续用于排除沉浸式翻译结果。
- 若要判断文本是否为目标语言，应结合可选源语言或轻量语言识别，不能只依赖 Script。

### 2. 自定义提示词可能命中错误缓存

当前 `promptHash()` 只包含：

- System Prompt 模板。
- User Prompt 模板。
- `targetLang`。

但提示词还支持 `{sourceLang}`、`{itemTitle}` 等变量。点击翻译时会传入真实书名，预处理当前把 `itemTitle` 设为空字符串，但两者仍可能得到相同的缓存签名。更改 `sourceLang` 后，旧缓存也不会自动失效。

相关代码：

- `src/modules/cache/keys.ts` 中的 `promptHash()`。
- `src/modules/translate.ts` 中的 `cacheSignature`。
- `src/modules/preprocess/job.ts` 中的 `promptSignature` 和预处理 Prompt 变量。

建议：

- 给缓存签名协议增加版本号。
- 把所有影响输出的静态参数纳入签名，包括 `targetLang`、`sourceLang` 和相关格式化版本。
- 若模板使用 `{itemTitle}`，预处理应读取与点击翻译相同的书名。
- 对预处理无法稳定提供的变量，可以禁止缓存共用或给出明确警告。

### 3. 预处理的探测请求没有复用结果

批处理开始前会先对第一条执行一次单条翻译，用于探测输出行数。该结果只用于计算 `expectedLines`，没有写入缓存；随后第一条会在正式批次中再翻译一次。

相关代码：`src/modules/preprocess/job.ts` 中的 `probeExpectedLines()` 和批次构建逻辑。

建议让探测方法返回“行数 + 翻译结果”，并立即写入第一条，然后从待处理列表中移除该条。

### 4. “请求间隔”不是真正的全局限流

当前每个 worker 在自己的请求结束后独立等待。当并发数为 8 时，8 个 worker 仍可以在几乎同一时刻发出请求，因此该设置不能保证任意两次请求之间的最小间隔。

建议：

- 增加任务级共享 rate limiter，在每次请求启动前获取令牌。
- 对 HTTP 429 读取 `Retry-After`。
- 取消任务时中断所有进行中的请求、延时和重试退避。
- 确认窗口中的请求数应表示范围或最低估计，因为探测、重试和批次拆分都可能增加请求数。

### 5. 预处理取消只在批次之间生效

`cancelActiveJob()` 只把 `cancelled` 设为 `true`。已经发出的请求、请求内部重试和当前延时不会立即结束。高并发下，用户点击“停止”后仍可能等待多个请求完成。

建议任务拥有一个统一的 `AbortController`，传入每次 LLM 请求和可取消的 sleep。完成取消后，再将持久化状态标记为 `paused`。

### 6. 任务运行时仍可清空全部缓存

单本删除会检查当前任务，但设置页的“清空缓存”按钮没有检查 `isJobRunning()`。

如果在预处理期间清空，后台任务可能在删表后继续写入，并重新创建部分缓存，导致“已清空”和实际状态不一致。

建议：

- 任务运行时禁用全局清空按钮。
- 或者点击后提示用户先停止任务。
- 只有在所有请求和数据库写队列完全结束后才允许清理。

### 7. 自动预处理的 `started` 状态过早记录

`src/modules/preprocess/menu.ts` 在确认附件类型和成功启动任务前，就把 `itemID` 放入 `started` 集合。

如果当时已有另一个任务、服务商未配置或任务启动失败，该书在本次 Zotero 会话中也不会再自动尝试。

建议让 `startPreprocess()` 返回结构化结果，只在真正启动或确认无需再处理后记录状态。

## P1：设置页与可配置性

### 8. 设置页内容过长，基础设置和高级设置混在一起

当前 `addon/content/preferences.xhtml` 是一个超过 500 行的单页设置面板，从服务商配置一直排列到提示词编辑和预处理任务管理。

建议拆分为四组或四个标签页：

1. **基础设置**：服务商、API Key、模型、目标语言、测试连接。
2. **翻译行为**：自动翻译、上下文、快捷键、流式输出。
3. **缓存与整本预翻译**：缓存策略、任务参数和任务列表。
4. **高级设置**：温度、tokens、超时、提示词、调试日志。

预处理服务商默认为“跟随翻译服务商”，该区域可以默认折叠，只在用户选择独立配置时展开。

### 9. 缺少“测试连接”和“当前生效配置”

目前的“获取模型”只能证明模型目录接口可访问，不能证明选中的模型具有 Chat Completion 权限、请求格式兼容或能正常输出。

建议：

- 增加“测试连接”按钮，发送一个极小的测试请求。
- 显示延迟、服务端返回的实际模型、是否支持流式和具体错误原因。
- 显示当前最终生效的 baseURL 和模型，而不只依赖占位符。
- 明确显示预处理是否跟随主服务商。

### 10. 目标语言和源语言没有出现在设置页

`targetLang` 是插件的核心配置，但目前只能通过 `about:config` 修改；`sourceLang` 也没有界面。

建议：

- 增加常用目标语言下拉框和自定义输入。
- 源语言默认为自动检测，允许用户显式指定。
- 预处理的语言过滤应优先根据翻译方向，而不是默认根据 Zotero 界面语言猜测。

### 11. Prompt Profile 的数据结构支持 User Prompt，但设置页只能编辑 System Prompt

`PromptProfile` 同时包含 `system` 和 `user`，但设置页的 `PromptEditorIds` 和提交逻辑只处理 `system`。用户只能在结果面板临时修改已渲染的 User Prompt，无法永久定制模板。

建议：

- 为每个模板提供 System / User 两个编辑区。
- 提供可用变量的点击插入菜单。
- 增加使用当前选区的渲染预览。
- 检查 `{text}` 是否缺失、输出结构是否可批处理，并在不兼容时给出警告。
- 明确显示“已保存”、“有未保存修改”或使用防抖自动保存。

### 12. 数值配置没有统一的运行时限幅

多数数值输入在写入偏好时只检查“有限且大于 0”。HTML 上的 `min`、`max` 不能替代运行时校验，手动输入、`about:config` 或旧版本偏好都可能越界。

建议为每个数值配置定义统一 schema，包含默认值、最小值、最大值和单位，设置页与运行时共用同一个 normalize 函数。

需要重点限制：

- `requestTimeoutMs`。
- `maxTokens`。
- `prefetchConcurrency`。
- `prefetchBatchSize`。
- `prefetchMaxSentencesPerWord`。
- `maxSentenceChars`。
- 词数和字符数判定阈值。

`prefetchDelayMs` 的界面最小值为 1，但运行时明确支持 0，两者也应统一。

### 13. 缓存开关与预处理的语义不一致

`cacheEnabled` 只在点击翻译链路中控制缓存查询和写回，预处理任务本身不检查该开关。

这会导致用户关闭“启用本地翻译缓存”后，仍然可以消耗 API 额度生成预处理缓存，但点击翻译又不会查询它。

可选方案：

- 缓存关闭时禁用写回、预翻译和缓存匹配子选项。
- 或把开关改名为更准确的“划词时使用本地缓存”，并让预处理有自己的开关。

### 14. 开关之间的依赖关系应在界面中反映

建议增加以下动态状态：

- 关闭缓存时，置灰缓存写回、严格匹配、单条回退和预翻译。
- 关闭“划词时带出所在句子”时，明确提示预处理无法工作。
- 开启自动翻译时，说明它会在每次选择文本时发起请求并可能产生费用。
- 自动翻译和打开 EPUB 自动预翻译可以在首次开启时显示一次确认。

### 15. API Key 的安全性与管理体验可以改善

当前 API Key 以明文保存在 Zotero prefs，并且为了服务商切换，同时保存在扁平配置和 `providerConfigs` JSON 中。文档已经说明这一点，但仍可以改善管理体验。

建议：

- 增加显示/隐藏 Key 和“清除当前服务商 Key”。
- 显示明文保存提示，并说明是否会随配置导出或同步。
- 调研 Zotero/Firefox 登录管理器是否适合保存 Key；若不适合，至少避免不必要的多份重复。
- 日志、错误详情和调试导出始终不得包含 Key。

## P2：生命周期、界面和工程质量

### 17. 划词弹窗的流式状态会按选区持续累积

`src/modules/reader/popupStream.ts` 为每个 `Document` 保存一个 `Map<string, StreamState>`。已断开 DOM 的 slot 会在同一 key 再次被访问时移除，但 key 本身和 `partial` 没有 TTL、数量上限或完成后的删除逻辑。

建议：

- 翻译完成或失败后定时删除该 key。
- 每个文档只保留最近若干个选区。
- 阅读器关闭时主动释放对应状态。

### 18. 多击选择逻辑会强引用已销毁的文档和 iframe

`src/modules/reader/multiClickSelection.ts` 使用强引用的 `Map<Document, ...>`、`Set<MutationObserver>` 和保留 frame 的清理闭包。这些对象只在插件关闭时统一释放。

EPUB 章节和阅读器 iframe 可能反复创建、销毁，长时间阅读后可能累积不再可见的 DOM、监听器和观察器。

建议：

- 按阅读器实例管理 disposer，阅读器关闭时立即释放。
- MutationObserver 同时处理 `removedNodes`，清理移除 iframe 的监听器。
- 可以使用 WeakMap 的状态尽量不使用强引用容器；需要遍历清理时，应由上层阅读器生命周期保管 disposer。

### 19. 设置页无条件每秒读取预处理任务

`startTaskRefresh()` 在设置窗口存活期间每秒调用 `refreshPreprocessTasks()`，即使没有任务运行，或用户正在查看其他设置页。

建议：

- 优先使用任务进度订阅/事件通知。
- 若保留轮询，只在有运行中任务且设置面板可见时轮询。
- 任务结束后执行一次最终刷新，然后停止定时器。

### 20. 结果面板缺少响应式、暗色主题和无障碍支持

`src/modules/ui/resultPanel.ts` 使用固定 `380px` 宽度和硬编码浅色颜色，同时缺少对话框或状态区域的 ARIA 语义。

建议：

- 宽度改为 `min(380px, calc(100vw - 32px))`。
- 读取 Zotero/系统主题变量或通过 `prefers-color-scheme` 适配暗色模式。
- 增加 `role="region"`/`dialog`、`aria-live` 和明确的按钮 `aria-label`。
- 支持 Escape 关闭、合理的焦点移动和键盘操作。
- 避免只用颜色表示词/句状态。

### 21. 弹窗结果缓存只保留每个 Document 的最后一条

`popupTranslation.ts` 使用 `WeakMap<Document, PopupTranslationEntry>`，因此当选区 A 仍在请求、用户立即选择 B 时，B 会覆盖对 A 的请求记录。A 的网络请求仍会继续，但后续弹窗无法再复用它。

为保留多选区并发翻译，可以使用有 TTL 和数量上限的 Map，让各选区的请求和结果能够独立复用。

### 22. 错误和任务结果过多依赖日志

`startPreprocess()` 捕获异常后只写 warning，调用方拿不到“完成/取消/拒绝启动/失败”等结构化结果。设置页和自动预处理因此难以显示准确状态或判断是否重试。

建议返回类似以下结果：

```ts
type PreprocessResult =
  | { status: "done"; done: number; failed: number }
  | { status: "paused"; done: number; failed: number; reason?: string }
  | { status: "cancelled"; done: number; failed: number }
  | { status: "not-started"; reason: string }
  | { status: "failed"; reason: string };
```

### 23. 可以补充真实 Zotero 交互层测试

现有单元测试对纯函数和 LLM 响应解析的覆盖很好，但以下风险主要发生在编排和真实 DOM 层：

- 连续按快捷键时，多个翻译请求的状态隔离。
- 设置页服务商切换和输入保存。
- 清空缓存与预处理并发。
- 阅读器 iframe 添加/移除后的监听器清理。
- 弹窗重新渲染、切换选区和流式输出。

建议在现有 Vitest 之上增加一层组件/编排测试，并保留少量 `zotero-plugin test` 冒烟测试。

### 24. 缺少持续集成和格式检查收口

仓库当前没有 GitHub Actions。建议增加 CI，至少执行：

```text
npm ci
npm test
npm run typecheck
npm run lint:check
npm run build
```

当前 `lint:check` 在 Prettier 阶段失败，需要格式化的文件包括：

- `docs/configuration.md`
- `docs/提示词模板/tagalog-chinese/划句.md`
- `docs/提示词模板/英中/划句.md`
- `docs/提示词模板/英中/划词.md`
- `prefs.js`
- `README.md`
- `README.zh-CN.md`
- `src/modules/preprocess/batch.ts`
- `src/modules/preprocess/job.ts`

### 25. README 中的测试数和部分说明已经过期

`README.zh-CN.md` 徽章仍显示 `168 passing`，当前实际为 311 个测试。建议不再手工维护这个数字，改为 CI 状态徽章，避免频繁过期。

## 建议实施顺序

### 第一轮：正确性和费用保护

1. 修复同文字体系语言被拦截的问题。

1. 复用行数探测的翻译结果。

3. 让任务取消中断请求、延时和退避。
4. 让 `startPreprocess()` 返回结构化结果。
5. 修正自动预处理的已启动记录时机。

### 第三轮：设置页重构

1. 拆分基础、翻译行为、缓存/预处理、高级四组。
2. 增加测试连接、生效配置、目标语言和源语言。
3. 补齐 System/User Prompt 编辑与预览。
4. 统一数值 schema 和开关依赖关系。
5. 改善 API Key 和本地服务商配置体验。

### 第四轮：长期稳定性与发布质量

1. 按阅读器生命周期清理文档、iframe、observer 和弹窗状态。
2. 将任务列表从无条件轮询改为事件更新。
3. 完善暗色主题、键盘操作和 ARIA。
4. 增加 CI、编排测试和 Zotero 冒烟测试。
5. 清理文档中的过期数据。
